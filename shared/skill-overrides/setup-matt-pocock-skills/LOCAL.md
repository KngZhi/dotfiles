## Local conventions

For KngZhi repositories, when handling, planning, or explaining a Linear-related
step, read `linear-usage` and its workspace reference in the current turn before
answering or acting
(`~/.agents/skills/linear-usage/SKILL.md`; source fallback:
`~/repo/dotfiles/shared/skills/linear-usage/SKILL.md`). Read the shared and
repository instructions and any existing `docs/agents/issue-tracker.md` first.
They establish Linear as the engineering tracker; GitHub remains the code/PR/CI
surface. Reuse the known workspace/team and JUN state/owner triage mapping from
the common entrypoint. These settled choices replace upstream Section A's GitHub
default and Section B's request to confirm/create triage-role labels.

Record the applicable mapping in the repo's setup documents by pointing to the
shared entrypoint rather than copying its routing/state table. Ask only for a
missing repository project or an unresolved domain-doc choice. Preserve current
repository document content and the upstream review step for actual setup edits.
Repositories outside KngZhi retain the upstream tracker-selection workflow.
