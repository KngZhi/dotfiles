# UI Prototype

Start from the existing screen and the user's design question. Reuse its framework
and styling conventions. Make meaningful variations when comparison is useful;
a requested single direction does not need extra alternatives.

Use realistic sample content and inspect the key interaction at the relevant
viewport. If multiple variants are built, make switching between them obvious.
Keep experimental routes and assets identifiable.

Finish with a runnable preview and the concrete design conclusions. Polish only
what is needed to judge the question; avoid building unrelated backend behavior.
