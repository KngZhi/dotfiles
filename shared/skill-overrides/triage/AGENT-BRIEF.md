# Agent Briefs

Describe the requested next action, current behavior, desired behavior, important
interfaces, scope, and verifiable acceptance criteria. For a PR, distinguish what
the diff already implements from what remains.

Use the approved request and discussion as authority. A generated brief summarizes
those decisions; it does not override later user direction or silently add scope.

Concrete paths and types are useful evidence when they help an implementer find
the code. Pair them with behavior and intent so the brief survives refactoring.

Use the project's existing issue format. Keep the brief as short as it can be
while preserving the decisions an implementer needs. Record material unknowns
rather than inventing answers.
