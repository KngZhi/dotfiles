# 下单前取数

所有命令使用现有 `k2046` CLI。先运行相应子命令的 `--help` 核对安装版本；证据文件放私有任务目录，保留查询时间、ERP 业务日期及其时区。聊天的中国日期不能直接当作智利订单日期。

## 客户和历史

```sh
k2046 customer list -s '<独立身份线索>' --offset 0 -l 100 -o json
k2046 sale list --customer-id <id> --offset 0 -l 100 --order-by createTime --order desc -o json
k2046 sale get <历史单id> -o json
```

客户查询没有 `--fetch-all`；按分页读取全部候选。客户 ID、完整电话或 RUT、姓名加摊位和地址是身份依据；聊天标题只作线索。整串市场名查不到时拆成独立线索查。身份仍有歧义时问一个针对性问题，不能自动新建客户来绕过。

从最近相关页或已知历史单确认正常销售仓、数量单位和该客户成交价，无需读取全部成交历史。价格依据依次为用户最后一次明确修正、已接受草稿、相关且可核实的客户历史。当前商品默认价只是对照；实际约定价格缺失时询问，不凭空补价。

## 精确货号与库存

```sh
k2046 product list -s '<SKU>' --limit 20 -o json
k2046 stock list -s '<SKU>' --precise-pn --warehouse '<仓库id>' --show-zero --fetch-all -o json
```

商品搜索可能模糊匹配，核对精确 `productNumber` 和 `productId`；候选多时继续分页。不得把相似货号、图片风格或旧消息中的货号替换成用户已更正的货号。

从商品主数据读取包装倍率、基础计价单位及价格；从历史单、现有仓库字典和库存行确定仓库名称与 ID。每行显式填写已核实的 `warehouseId`，避免 CLI 的默认仓成为业务判断。分别查询正常销售仓和 lazon，保留各自库存行和时间。无行、零、负数各自如实记录，不用跨仓合计替代销售仓库存。

## 包装和金额

| 来源数量 | JSON 字段 | 必须核实 |
| --- | --- | --- |
| 1 箱或 1 件 | `boxNumber: 1` | 实际 `packingBox` 和每基础单位价格 |
| 袜子 2 打 / docena | 通常 `unitNumber: 2` | 该商品基础单位确为打、历史录法一致 |
| 以 12 个组成一打的商品 | `bigBagNumber` 等实际包装字段 | `packingBigBag`、基础单位及单价换算 |

一箱的行金额 = 箱数 × `packingBox` × 每基础单位单价。显示“一打”的商品，未必以打为基础计价单位。混合包装逐行显式给 `boxNumber`、`bigBagNumber`、`bagNumber`、`unitNumber`，未用字段为零。

合成示例：某商品一箱含 40 打、每打 1500 CLP，2 箱合计 120000 CLP。另一商品每大包 12 个，一打售价 7200 CLP，则基础单价为每个 600 CLP。示例不能替代实时主数据。

截图的 `×n` 只表示当时显示单位，不能直接当箱数。报价、购物车总额和算式不能单独证明货号。合计不符时定位冲突行，不能改数量或价格去凑总额。

## 草稿确认

把每行货号、数量、单位及有依据的价格说清。最新明确更正只改变对应行，其余已接受行保留。用户随后要求下单时执行；只对仍缺的数据发问。
