# 费用参数与成本计算

命令从技能目录运行。工作簿流程只用本技能的 TypeScript 引擎，不调用 chile-mono 或其他
Python 成本脚本。金额默认值与计算行为以 `src/business-rules.ts` 和 `src/calculate.ts`
为准；变更业务规则时同步核对本文。

## 输入

字段、计价单位和问题标注遵循 [工作簿契约](../../container-intake/references/workbook.md)；
表头映射读取 `container-intake/references/template-schema.json`，不按列位置猜字段。旧表仅兼容读取。

- 逐行保留商品销售及库存单位：袜子为 `打`，女士内裤为 `条`（不能换成打）；单价、装箱数和
  总数量一致，已规范化的行不能再次乘除 12。引擎仍兼容旧表的 `双` 并在计算前转换；空单位只兼容
  已确认口径的旧模板，不表示新整理表可以省略单位。
- 同柜可有不同单位，数量分单位汇总；同一货号单位冲突或单位不明时交回材料整理。
- `config` 的真实必填项为海运费（USD）和货柜号。
- 单价来自材料，不从零售价反推。条码从材料或 K2046 取得时保留来源，不以组件条码代替组合货号的主条码。

## 费用来源与默认值

| 字段 | 当前规则 |
| --- | --- |
| 内陆费（CNY） | 显式金额优先；否则须指定承担方：厂家为 0（须有厂家承担的事实依据），我方为 5500 |
| 卸柜费（CLP） | 缺省 125000，实际值覆盖 |
| 清关杂费（CLP） | 未取得实际金额时暂估 1500000；到港后用实际值替换 |
| USD-CLP | 缺省实时查询 open.er-api.com；失败则保留失败状态，不硬编码回退 |
| USD-CNY | [中国银行外汇牌价](https://www.boc.cn/sourcedb/whpj/)美元现汇卖出价，每 100 美元报价 ÷ 100；读取失败则停止，不用交叉汇率回退 |
| CNY-CLP | 缺省 `(USD-CLP + 12) / USD-CNY`，12 为每美元的比索手续费；显式实际汇率覆盖 |
| IVA计税货值USD | 缺省 18000 美元/柜，可逐柜指定（如 20000） |
| IVA | 已有实际税单金额用实际值；缺省或 0 时按下式估算 |

- 例：`(930 + 12) / 6.7 = 140.597014925…`。人民币货款和内陆费用 CNY-CLP；美元海运费与 IVA
  估算用原 USD-CLP，12 比索手续费不进入 IVA。
- IVA 估算是用户于 2026-09-23 确认的经营规则（[决定记录](https://github.com/KngZhi/chile-ops/blob/main/decisions/2026-09-23-container-iva-estimated-taxable-value.md)）：
  `IVA = (IVA计税货值USD + 海运费USD) × USD-CLP × 19%`。海运另加，不按实际采购货值乘 30%。
  这是经营估算，不是法定税务计算声明。逐柜指定计税货值：
  `npm run prepare:config -- <柜.xlsx> --iva-goods-value-usd 20000`。
- 显式 0 必须保留。记录默认、推导、实时获取、暂估与实际费用的区别。
- 实际结算汇率或用户指定的历史汇率可显式填写。材料索引记录中行报价列、发布时间（北京时间）和来源；
  config 只保留汇率数值及简短来源，不放整张牌价表。

## 旧表重算

- IVA：读取保留的公式。识别出旧自动估算公式或明确「估算」说明时，忽略其正缓存，按新规则重算；
  正数且明确「实际」说明的保留。正数来源不明、未知公式、公式与「实际」说明冲突时停止，先核来源，
  再用说明「实际/估算」或 `--iva <实际CLP金额>` 明确。不把未标来源的历史数字自动当实际或估算，
  也不批量覆盖现有业务表。新表在 config 保留可编辑的计税货值参数，IVA 公式引用它并标「估算」。
- 清关杂费：标明为旧默认的更新至当前默认；实际费用不覆盖。
- 汇率：标注为默认的 CNY-CLP 135 改为上述公式；从比索交叉推导的旧 USD-CNY 改为中行报价；
  有凭证的实际兑换汇率保留。

## 命令与验证

```bash
npm run check
npm run validate <容器.xlsx>
npm run prepare:config <容器.xlsx> -- --inland-payer factory
npm run prepare:config <容器.xlsx> -- --clearance-misc-fee <实际CLP金额>
npm run process <容器.xlsx>
```

只需要成本引擎时使用 `npm run calculate <容器.xlsx>`。

校验 EAN-13 格式和校验位，查询货号、供应商与分类。区分新货号、缺分类等可处理问题与会改变
成本或身份的错误；调查验证失败的原因，不默认加 `--force` 忽略它。分类处理见
[classification.md](classification.md)。

引擎负责单位转换、体积处理、费用分摊和散件合并；不另写成本公式，也不手动重复转换或合并。
前置整理表的显式 `散件数` 直接进入总数量与费用分摊，不能遗漏或再折算成整件。旧格式（无散件列）
同货号多行时，件数大于 1 的行提供标准装箱数，件数为 1 且装箱数不同的行作为散件累加到整件行；
多个标准不一致或没有可确定的整件行时，对照引擎结果和原材料再处理。生成后核对总数量、货值、
单位、费用与合并结果。

## 成本结果表

「成本计算结果」各档售价按商品销售单位与成本价比较，不再除装箱数。毛利率 =（售价 − 成本价）/ 售价。
生成的 xlsx 和在线表用条件格式提示：成本价、箱价格、大包价格、包价格、单价为 0 或空白，
分类1、分类2 为空白，以及毛利率低于 25%（恰好 25% 不提示）。补全后提示自动消失；不把缺失值
改成零，不自动调整售价或分类。输出后处理依赖 Python 3 标准库，失败时不报告生成成功。

结果写入该柜原 Google 表格的「成本计算结果」工作表后，运行相邻 container-intake 的
`uv run --with gspread --with google-auth-oauthlib --with openpyxl scripts/format_cost_sheet.py <原货柜表格ID>`
统一在线样式（白底黑字，冻结首行和货号列，品名换行，价格显示整数和千位分隔）。只在需要业务解释的
问题单元格写批注，不给正常单元格或每个表头重复添加通用说明。原数值不为美化而改变。读取实际
Google 格式与效果验收，不以 xlsx 规则成功代替显示验收。
