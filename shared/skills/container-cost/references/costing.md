# 费用参数与成本计算

命令从技能目录运行。正式工作簿流程使用 TypeScript 引擎；无需调用外部
Python helper 或 chile-mono 的另一份成本脚本。

## 工作簿契约

字段、样式和计价单位遵循 [前置整理的工作簿契约](../../container-intake/references/workbook.md)。
新交接表的 `计价单位` 为 `打`，单价、装箱数和总数量已经同时规范化，不能再手动乘除 12。
引擎仍兼容旧表的 `双` 并在计算前转换；空单位仅兼容已确认口径的旧模板，
不表示新整理表可以省略单位。旧表混用单位或单位不明时先交回材料整理。

`config` sheet 的真实必填项为海运费（USD）和货柜号。
单价来自材料，不从零售价反推。条码从材料或 K2046 取得时保留来源，
不以组件条码代替组合货号的主条码。

## 费用来源与默认值

| 字段 | 当前规则 |
| --- | --- |
| 内陆费（CNY） | 显式金额优先；否则须指定承担方。厂家为 0，我方为 5500 |
| 卸柜费（CLP） | 缺省 125000，实际值覆盖 |
| 清关杂费（CLP） | 未取得实际金额时暂估 1350000；到港后用实际值替换 |
| CNY-CLP | 缺省 135，显式值覆盖 |
| USD-CLP | 缺省实时查询 open.er-api.com；失败则保留失败状态，不硬编码回退 |
| USD-CNY | 缺省按 USD-CLP / CNY-CLP 推导 |
| IVA | 缺省或 0 时使用引擎估算公式 |

显式 0 也必须保留。记录默认、推导、实时获取与实际费用的区别。
金额与计算行为以 `src/business-rules.ts` 和 `src/calculate.ts` 为准；
变更业务规则时同步核对本表。

## 命令与验证

```bash
npm run check
npm run validate <容器.xlsx>
npm run prepare:config <容器.xlsx> -- --inland-payer factory
npm run prepare:config <容器.xlsx> -- --clearance-misc-fee <实际CLP金额>
npm run process <容器.xlsx>
```

只需要成本引擎时使用 `npm run calculate <容器.xlsx>`。
使用 `factory` 必须有厂家承担内陆费的事实依据。

校验 EAN-13 格式和校验位，查询货号、供应商与分类。区分新货号、缺分类等
可处理问题与会改变成本或身份的错误；调查验证失败的原因，不默认加
`--force` 忽略它。分类处理见 [classification.md](classification.md)。

引擎负责单位转换、体积处理、成本计算与散件合并。生成后核对总数量、
货值、单位、费用与合并结果，不再次手动重复转换或合并。

散件规则：同货号多行时，件数大于 1 的行提供标准装箱数；件数为 1 且
装箱数不同的行作为散件，累加到整件行的散件数。多个标准不一致或没有
可确定的整件行时，检查引擎结果和原材料后再处理。

成本完成后更新 containers.org 的供应商和成本文件路径。
涉及价格或实际入库的下一步按用户已授权的范围继续。
