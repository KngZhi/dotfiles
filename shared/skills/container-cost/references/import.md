# K2046 导入

## 预检

先满足 [SKILL.md](../SKILL.md#导入门槛) 的导入门槛。用户修改成本表后，重新读取并导出「成本计算结果」，
不能继续使用旧的本地成本文件。

每次导入前运行 `npm run import:checked -- <成本Excel> --check-only`；正式导入走同一入口
`npm run import:checked -- <成本Excel> <参数>`，每次调用都会重新检查。直接调用
`k2046 purchase import-container` 只用于只读预解析，不得正式写入。

预检发现的问题按 [问题标注规则](../../container-intake/references/workbook.md#问题标注) 回标到具体单元格，
写明问题、处理要求及是否阻断导入。红色或批注被清除不代表问题已解决，仍须核对实际数据与来源。

## 范围与字段

导入会创建采购单，正常导入可能同时提交。先确认导入本身在用户请求范围内，并核对准确的文件、柜号、
仓库、供应商、分类、出柜时间和 ETA。

- K2046 前端没有独立的「发柜时间」字段，所以借用「发票时间」`invoiceDateTime` 保存这柜实际发出的
  时间：不代表发票开具时间，也不能填建单日期、导入日期或 ETA。`shipmentDate` 保存预计到港 ETA；
  ETA 不表示实际到仓或已入库。两者分别取自 config 的发柜日期和 ETA。
- 按原始发柜记录确定实际发出日期；只有记录无法确定或互相冲突时才向用户核实。只有日期时以当天
  `00:00:00` 保存，有明确时分秒时保留原值；使用 K2046 服务端本地时间，不做时区换算。
- 采购单备注默认留空。柜号、数量、单位、ETA 解释、费用计算规则、核对过程和问题批注都不写进备注，
  放在成本表或归档报告；只写用户明确提供的业务备注。清空备注必须实际传入空字符串并回读确认，
  省略 `memo` 不等于清空。
- 逐货号核对整理表与 K2046 的库存单位和包装层级（女士内裤按条，袜子按打）。不能把按条的成本、
  数量和装箱数改成按打后导入；同柜不同商品无需统一成同一单位。

## 命令

检查当前 CLI 帮助后选择操作：

```bash
k2046 purchase import-container <成本Excel> --parse-only
npm run import:checked -- <成本Excel> --container-no <柜号> --shipment-date <ETA>
k2046 purchase update-invoice-time <采购单ID> --invoice-date-time "<实际发柜日期> 00:00:00"
```

对应 MCP 工具为 `update_purchase_order_invoice_time`，传入 `orderId` 和 `invoiceDateTime`。

- `--parse-only` 和当前 CLI 的 `--dry-run` 都只上传临时文件并解析行，不创建采购单、不调用
  import-parse/import-commit，也不模拟按供应商拆单。以当前 CLI 帮助及实现为准。
- 13 列标准整理表是成本输入，不能直接套用 K2046 导入映射；先由成本程序生成成本结果，再按结果的
  实际表头映射。改输入模板不等于改服务器导入列。
- 标准成本表若为 18 列（含「散件数」），不能套用 CLI 默认 17 列映射，否则仓库和分类会错位；
  先核对每一列并显式指定映射，再检查解析结果。
- 确认所用工具能设置 `invoiceDateTime`，导入后独立回读；命令不支持该字段时，通过支持它的界面
  或接口补写，不能遗漏或只写进备注。

## 完成

保留导入返回的采购单 ID，核实创建与提交状态。部分失败时先检查已有采购单，恢复未完成步骤，
避免重复导入。只有实际完成后才更新 containers.org 的 `PO_IDS` 和入库 checklist。

如请求还包括图片整理，按柜号整理产品图片并单独核实对应 checklist。报告已解析、已创建、已提交
和仍未完成的阶段。
