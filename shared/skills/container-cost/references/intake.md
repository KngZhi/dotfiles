# 货柜材料接收与自动补全

## 固定位置

- 微信文件根目录：`~/Library/Containers/com.tencent.xinWeChat/Data/Documents/xwechat_files/chenjunwei590505_80b3/msg/file`
- 待整理目录：`~/Library/CloudStorage/OneDrive-Personal/00_待整理货柜`
- 成本输入目录：`~/Library/CloudStorage/OneDrive-Personal/source_files/containers`
- 成本输出目录：`~/Library/CloudStorage/OneDrive-Personal/source_files/containers/generated`
- 成本引擎：技能内 `src/calculate.ts`（唯一事实来源）

## 执行顺序

1. 扫描用户指定文件、待整理目录以及微信文件根目录中的近期相关文件。
2. 读取 XLSX、PDF、图片和文本内容；不要仅根据文件名判断。
3. 提取柜号并聚合同一票材料。柜号优先匹配 ISO 6346 形式：
   `4 个大写字母 + 7 个数字`。
4. 使用以下辅助键校验分组：
   - 海运提单号或订舱号
   - 货代参考号
   - 船名与航次
   - 起运港与目的港
   - 供应商、箱数、重量和体积
5. 在待整理目录创建或复用：
   `<材料日期>_<供应商>_<柜号>/`
6. 把原始材料复制进货柜目录。保留来源文件，不移动、不删除。
7. 创建或更新 `00_材料索引与待补.md`。
8. 根据提单或船名判断承运人，使用 Chrome 打开承运人官方追踪页面。
9. 按柜号查询并记录船期数据。只把柜号发送给追踪网站，不上传本地材料。
10. 对照技能内 TypeScript 成本字段，标记 `已取得`、`默认值`、`待确认` 或 `缺失`。
11. 数据足够时，准备符合 `data` 和 `config` sheet 约定的成本输入文件；否则停止在待补清单，不运行成本计算。

## Chrome 船期查询

### 通用规则

- 优先承运人官网，不使用聚合网站作为唯一证据。
- 从网页当前可见结果读取：
  - 柜号
  - ETA（目的港预计到达）
  - ETD（起运港预计离港，如有）
  - 当前或最近运输节点
  - 最近节点日期和地点
  - 船名与航次
  - 起运港、目的港和码头
  - 官网结果更新时间
- 同时记录本次查询的本地日期、来源 URL 和承运人。
- ETA 变化时保留“上次 ETA → 当前 ETA”的简短记录。
- 网页要求登录时，请用户在 Chrome 完成登录后继续。
- 出现 CAPTCHA 时，先请用户接管处理。

### MSC

1. 打开 `https://www.msc.com/en/track-a-shipment`。
2. 选择 Container/Bill of Lading Number。
3. 输入柜号并查询。
4. 读取 `POD ETA`、时间线、船名航次和最新节点。

## 成本引擎字段

每次处理新货柜前，以技能内下列导出常量为准：

- `REQUIRED_DATA_COLUMNS`
- `REQUIRED_CONFIG_PARAMS`
- `OPTIONAL_CONFIG_PARAMS`

当前字段为：

### data sheet

| 字段 | 自动来源 | 规则 |
|---|---|---|
| 货号 | 装箱单/XLSX | 保留原值；可用 K2046 校验 |
| 品名 | 装箱单/XLSX | 保留原始品名 |
| 条形码 | 装箱单或 K2046 | K2046 补值时记录来源 |
| 单价 | 发票/装箱单 | 不从零售价反推 |
| 装箱数 | 装箱单或 K2046 | 冲突时优先材料并列出差异 |
| 件数 | 装箱单 | 不把总数量误作件数 |
| 总数量 | 装箱单 | 可校验 `装箱数 × 件数 + 散件` |
| 总立方 | 装箱单/货代资料 | 缺失可交给现有脚本分配，但要标记 |
| 供应商 | 材料或 K2046 | 简称可映射，完全不匹配时询问 |
| 计价单位（可选） | 装箱单/发票 | 只接受`双`或`打`；新袜子模板必须填写 |

### 袜子计价单位

- 供应商原始材料可以按`双`报价和统计，但成本文件及 K2046 销售单位统一为
  `打`（1打=12双）。
- 原始行按双时写`计价单位=双`。TypeScript 引擎会在成本聚合前把单价乘12、
  装箱数除12、总数量除12，并将单位改为`打`，所以货值保持不变。
- 已经按打整理的行写`计价单位=打`，引擎不再换算，避免重复乘除12。
- `计价单位=双`时，装箱数和总数量都必须是能被12整除的整数；否则立即停止，
  不生成带小数销售单位的成本文件。
- 空白计价单位只用于兼容旧模板，不做任何隐式转换。新袜子模板不得留空；
  不要仅凭品名猜测单位。

### config sheet

| 字段 | 单位 | 常见来源 |
|---|---:|---|
| 海运费 | USD | 货代费用通知 |
| 内陆费 | CNY | 显式金额优先；厂家承担=0；我方承担且无金额=5500 |
| 内陆费承担方（可选） | 文本 | `厂家` 或 `我方`；用于内陆费未显式填写时 |
| 卸柜费 | CLP | 缺省 125000；本柜实际值可覆盖 |
| USD-CLP | CLP/USD | 缺省时从 open.er-api.com 实时获取，失败则停止 |
| USD-CNY | CNY/USD | 缺省按 USD-CLP / CNY-CLP 推导 |
| CNY-CLP | CLP/CNY | 缺省 135；显式值覆盖 |
| 清关杂费 | CLP | 未到港缺省暂估 1350000；到港后用报关行/本地费用单实际值覆盖 |
| 货柜号 | 文本 | 提单、货代资料或官方追踪 |
| IVA | CLP，可选 | 税费单；缺省或 0 时脚本自动估算 |

海运费和货柜号必须来自真实材料，不得猜测。清关杂费在柜子未到港、无法取得
实际费用时按 CLP 1350000 暂估；到港取得实际金额后必须覆盖该暂估值，显式
`0` 或其它金额均优先。厂家承担内陆费的货柜在生成 config 时明确写
`内陆费=0`；不要只靠隐含默认。自动取得 USD-CLP 时记录来源和查询日期。

## 完成标准

- 所有材料已按柜号归档且原文件仍保留。
- 索引含当前官方 ETA 或明确的查询失败原因。
- 每项成本字段都有值、来源或缺失状态。
- 待用户补充列表只包含真正无法自动取得的字段。
- 未取得必填字段时不运行成本计算。
