# 库存盘点核查

把差异追到商品、仓库和具体单据，给出可复算的数量链，再决定需要补盘还是调整库存。

用户要求分析、查原因或核对代码时，进行只读调查。用户明确要求修正、提交或审核时，按已有授权执行相应范围，不另设重复审批；授权不能补足未知的实盘数量。单据写入结果不确定时，先查已落地结果，再决定下一步。

## 1. 固定这次盘点的范围

保存批次原始数据、状态、提交时间、仓库、商品 ID、当前货号、系统数、填报实盘、差额、箱规和打规。记录抓取时间，保留原始文件。

先确认数量单位和实盘覆盖：是否包括整箱、散包、货架、其他存放区。无法确认时，把实盘称作「填报数量」，继续查账。空白、自动预填零、人工确认零是不同证据；从合计零不能推断员工确实盘过。

优先查绝对差额大的款、系统负数、近期入库却填零、差额接近整箱或整打，以及系统只剩 1、241、301 等异常余数。系统接近零时，百分比失真，优先看件数和包装单位。数量形状用于选线索，不能直接证明把一箱录成一件。

## 2. 用身份补齐历史，而不是只搜当前货号

**以商品 ID 和仓库 ID 对齐原始明细，保留单据上的历史货号。** 当前货号、旧货号、条码只是辅助定位。同一商品可能由 `DF7226#` 改为 `DF7226`；`K4001#` 也可能就是有效现货号，不能全局去掉 `#`。

读 K2046 时先看 [K2046 取数与匹配](references/k2046.md)。至少覆盖：

| 数据 | 核查重点 |
|---|---|
| 入库单及明细 | 实际入库状态、总数量、箱/包/散件、商品 ID、仓库、修改时间 |
| 调拨单及明细 | 来源仓、目标仓、数量、出入库状态、执行时间 |
| 销售及退货 | 所属仓、实际影响库存的状态、退回方向，不能只看销售金额 |
| 历史盘点单及明细 | 新旧货号、商品 ID、调整前后数量、当前状态、是否取消 |
| 库存快照 | 同款各仓余额，能取得时加入历史快照定位跳变区间 |

把「没有找到」作为待验证结果：检查分页、查询时间范围、当前/历史货号和被客户端投影丢掉的字段。尤其不能在仅按现货号筛选后断言没有历史盘点。

逐页验证返回总数、实取行数和重复明细 ID。盘点列表只给单头时，要逐单拉全明细再按商品 ID 筛。把覆盖范围和未取得的数据写进取数清单；只有完整读过的范围才称为「当前接口可见全量」，不把它说成含删除日志和修改前版本的完整审计历史。

## 3. 分仓复算，再解释差额

用脚本按商品、仓库和同一库存单位计算；缺数量要报缺失，不能自动当零。先验证实际生效状态和去重键，再汇总。确认退货是否已包含在销售流水，避免重复计算。

```text
流水余额 = 期初 + 已入库 + 调入 − 调出 − 已出库销售 + 退货影响 + 有效盘点调整
盘点调整 = 调整后数量 − 调整前数量
账表差额 = 同时点系统余额 − 流水余额
实盘差额 = 填报实盘 − 盘点基准时点系统数
```

期初不明时，可用零起点作诊断，但必须标明假设，不能据此认定损耗或生成正式调整。若采用某次盘点作为余额锚点，只累计锚点之后的变动，避免再加一次该盘点差额。

按当前有效单据加总是余额核对，不等于还原全部历史。已取消盘点可能过去曾生效；历史操作顺序需要当时状态、执行时间或快照佐证。创建日期、单号日期、最后修改时间分别保留，不能用最后修改时间认定改了什么字段或是谁实际操作。

两仓一起核对：一仓多、另一仓少且数量接近，是查调拨的线索。先核实货物交接、源仓和目标仓，不能自动相抵。

对最大的差异给出一条明确数量链：哪个入库、哪些调拨、哪张盘点的「前 → 后」、后续发生了什么、如何到达现在余额。入库/调拨报表与原始明细交叉核对；有历史快照时检查数量链是否符合当时余额。

遇到「不改旧盘点，今天反而对上」时，读 [DF7226 案例](references/df7226-case.md)。把反事实算式与已证明的历史记录分开，不能从今天恰好对上倒推出当年实物一定正确。

## 4. 分开判断三个问题

| 问题 | 可以确认它的证据 |
|---|---|
| 清单有没有算错 | 本批原始数据、单位换算、显示及差额逐项一致 |
| 系统余额能不能解释 | 有效单据和期初能复算到同一时点余额 |
| 实物到底有多少 | 覆盖范围明确的人工复盘、交接或其他实物凭证 |

用户怀疑代码时，核对**实际线上版本**和本批真实记录：单仓取数、包装换算、空值/负数处理、页面显示、提交保存和审核目标。用隔离的离线依赖测试写入计划；生产页面检查保持只读。报告哪些环节实际执行过，不用「测试通过」代替生产写回证明，也不把一款算对说成全部代码无误。

如果发现是自己的筛选遗漏，直接说明，补拉受影响范围，并同步更正已交付的表格、结论和原始数据包。

## 5. 给出下一步，并按授权收尾

结果先说已定位的原因和证据，再说未确定的部分。通常交付逐款表：商品 ID / 新旧货号 / 仓库 / 盘点系统数 / 填报实盘 / 流水余额 / 历史调整 / 关键单号 / 下一步；大批量附原始 JSON 或 CSV、取数覆盖和复算结果。

- **流水能解释余额、填报实盘不同**：定位旧盘点或业务单据后，确认实物范围和数量，避免把旧账有解释当成旧账正确。
- **流水仍解释不了余额**：继续查期初、退货、取消/删除、历史修改和直接改库存；列出具体缺口，不能只停在「系统可能有问题」。
- **需要补盘**：给员工货号、单位、存放位置和待核实数量，重点区分漏数与真实零。
- **已授权调整且业务数量明确**：写前重新读取当前余额及批次状态，按实际写入接口的绝对数/差值语义构造目标，保留盘点后业务变动。绑定批次或单号防重，写后读回数量与状态。历史单的取消或删除可能影响后续库存，不能作为默认修正办法。

调整依据应是经确认的盘点事实。恢复到「未做旧调整的推算值」只是候选方案，不能代替实物核实。
