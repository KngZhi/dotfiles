# 标准货柜表

唯一列契约是 [template-schema.json](template-schema.json)，版本2。新表必须使用本技能
`assets/模板.xlsx`，部署副本为 `~/Library/CloudStorage/OneDrive-Personal/source_files/containers/模板.xlsx`。
不得从旧货柜表推导列结构。只保留 `data`、`config` 两个工作表，黑白样式。
问题单元格例外：凡 AI 核对发现的错误、缺项或未决差异，必须在对应单元格使用浅红底、深红字，
并添加该单元格的 Excel 批注/备注（Note），写清具体问题、依据或冲突值、需要补充/修正什么。
阻断导入的问题明确写「阻断导入」，如 SC109/C109 未拆分；不能只在外部报告列出。
空白必填单元格也须标红并备注。仅标记实际有问题的单元格，不把整行或正常的计价单位涂红。
不新增常驻备注列，不把核对备注写入 K2046 采购单 memo。问题解决并复核后移除对应红色和过期批注，
保留材料索引中的处理记录。无问题单元格继续使用黑白模板。
旧18/19列表仅供兼容读取；用户要求修改旧表时按本契约迁移并核对，不悄悄修改历史单据。

## data：固定13列

| 列 | 字段 | 填写规则 |
|---|---|---|
| A | 货号 | 文本，匹配完整商品货号 |
| B | 条形码 | 文本；缺主条码保留空白并记录例外，不能用组件条码代替 |
| C | 品名 | 识别商品及规格 |
| D | 图片 | 已有图片保留，非计算必填；无图不伪造 |
| E | 供应商 | 来源及K2046供应商归属 |
| F | 计价单位 | 袜子打、女士内裤条；其他商品按已确认销售及库存口径 |
| G | 采购单价（元） | 每个F列单位的人民币采购价，仅数字；未知留空 |
| H | 标准装箱数 | 一整件含多少F列单位，不用尾货数量代替 |
| I | 整件数 | 非负整数，只有散件时可为0 |
| J | 散件数 | 非负整数，无散件填0；与F列单位一致 |
| K | 总数量 | 自动计算：H×I＋J |
| L | 货款合计（元） | 自动计算：G×K；缺价格或数量时留空 |
| M | 总体积（m³） | 本行整件及尾包的总分摊体积，有独立来源 |

删除工艺、长宽高、单箱立方和长备注；原运输包装件数、原件字段、来源及核对过程留材料索引。
价格单位通过列标题及F列表示，不写进数字单元格。货号及条码不使用科学计数法。
新增商品行在 `DATA_END` 前插入，复制公式与格式并扩展合计/IVA引用的明细范围；删除未使用空白行，不改列序或新增工作表。
`DATA_END` 后仅有一行整件数/货款/体积合计，以及按打、条分别汇总的数量和散件数。
不同单位不能相加；合计公式必须只覆盖明细，缺采购价时整柜货值不可显示为完整金额。

## 单位与尾货

先对照原件确定单位、采购价、标准包装和尾包归属，再用脚本执行转换和比对。
袜子原件为双时，单价×12、装箱数/总数量/散件数÷12。女士内裤始终按条销售及入库，
保留元/条、条/件、总条数。已规范化的行不能重复转换。
同柜可以有多种单位；同一货号的单位必须一致，不能为凑模板去改K2046商品档案。

尾货单独记散件，不形成新装箱规格，也不重新凑整箱。例如MF401：4件×80打＋110打尾货，
写H=80、I=4、J=110、K=430。源运输包装是5件，入库整件是4件，两者分别保留。
合并同货号时核对单价、单位和规格一致，累加数量、货值及总体积；不一致先核对来源。
总分摊体积包含尾包，不能仅用标准箱体积×整件数。原箱、压缩后实际体积和提单体积分开留证。

## config：参数 / 值 / 说明

参数由schema固定：货柜号、发柜日期、ETA、海运费、内陆费、卸柜费、清关杂费、
USD-CLP、USD-CNY、CNY-CLP、IVA。说明只保留币种、暂估、来源日期等必要信息。
发柜日期用于K2046的 `invoiceDateTime`；ETA用于 `shipmentDate`，两者不得混用。
厂家承担内陆费填0；未知费用留空。卸柜费默认125000 CLP、清关杂费暂估1500000 CLP。
汇率与IVA遵循 [成本规则](../../container-cost/references/costing.md)，不能自己补猜测金额：
- CNY-CLP = (USD-CLP＋12) / USD-CNY；USD-CNY取中行美元现汇卖出价÷100。
- IVA = (完整人民币货值 / USD-CNY＋海运费USD) × USD-CLP ×30%×19%。
- 缺货值、海运费或汇率时IVA留空；实际税单优先。发柜日期和ETA保留真实来源及查询日期。

## 逐列验收

每次保存后运行 `scripts/validate_workbook.py`。它读取同一schema，校验列序、类型、
数量/货值关系、分单位合计、config和公式缓存；报告绑定文件SHA-256。
它不判断来源真实性，`source_review` 保持 `NOT_PERFORMED`，不能把表内PASS当作可入库。
AI另对照原件和K2046核实身份、价格、单位、标准包装、尾包、图片、费用范围和体积口径，
在索引记录原文件及行号、对应关系、结果与待补。不得用生成表自身充当独立来源。
合理体积差异标为待来源审查，不为消除报告而机械改数。最终独立读回并检查可视排版。
