# 标准工作簿与计价单位

模板：`~/Library/CloudStorage/OneDrive-Personal/source_files/containers/模板.xlsx`。
先读取实际工作表、字段和样式，复用 `data` / `config`，不另造多种交付格式。

## 表格外观与字段

保留模板原有列顺序和黑白样式，不加彩色标题、条纹表格或状态配色。
单价列标题用 `单价（元/打）`，明细单元格只显示数字，不逐行重复写单位。
列宽、换行和数字格式可为可读性调整。货号和条码是文本，完整显示，不用科学计数法。
来源路径、版本差异和长篇核对记录放材料索引；表内备注只留必要的业务说明。
保留可用的商品图片；若图片仍在源文件，明确其位置，不伪造已补图。

`data` 需要货号、品名、条形码、单价、装箱数、件数、总数量、总立方、供应商，
最后一行用 `DATA_END`。沿用模板其余字段，增加 `计价单位` 列并填写 `打`。
`单价` 为 CNY/打，`装箱数` 为打/箱或打/包，`总数量` 为打；`件数` 仍是箱/包数。

`config` 只保留柜号、计算所需费用与汇率，用「参数 / 值 / 说明」简表。
说明只写币种、暂估或汇率日期等必要信息。厂家承担内陆费时直接填 `内陆费 = 0`，
不另加承担方行。船期、来源、处理状态和长篇证据放材料索引，不塞进参数表。
未知采购价或费用保持空白，不用 0 代替。除工作簿原有 `data`、`config` 外不加 sheet。
保留一行箱数、打数、货值和体积合计供核对，放在 `DATA_END` 后；成本程序只读取明细。

## 换算与核对

先确认源表计价单位，用数量单位、装箱规格和金额公式交叉核对，不只相信列标题。
对已确认按双的袜子：单价乘 12，装箱数和总数量除以 12；件数、货值和体积不变。
已按打的行保持原值。对已确认按条的商品，同样按 12 条/打换算；单位不明先列待补。
不能只换单价而留下双数，也不能把已换好的单价再次乘 12。

袜子可复用 `container-cost/src/calculate.ts` 的纯函数 `normalizePricingUnits`，
仅传有确定来源的数值行，输出标记为打；不因此调用 `calculate` 或 `process`。
尚缺价格的行仍换算已确认数量，单价和金额继续留空。

保存前后按源行核对：
- `件数 × 装箱数 = 总数量`，各供应商合计与原件相同；换算后的数量乘 12 可回到原双数/条数。
- `单价 × 总数量 = 货值`，单位转换前后逐行和整柜货值不变。
- 尾包保留源行及主货号归属；转换数量单位时不同时合并尾包，交给下游既有引擎。
- 未压缩箱体积、实际装柜体积和整柜提单体積分开留证，不能互相冒充或写错产品 boxVolume。

缺条码先只读匹配 K2046 同货号。系统已有无主条码商品保留空白例外，不能取组件条码代替。
原表与系统条码冲突、新货号或混合货号分别记录，不能只靠格式校验就认定可交接。

保存后独立读回字段、单位、行数、数量、货值和公式缓存，并查看工作表排版。
业务上缺什么就标什么；没有事实依据的价格不能因凑齐模板而填入。
