# 标准工作簿与计价单位

模板：`~/Library/CloudStorage/OneDrive-Personal/source_files/containers/模板.xlsx`。
先读取实际工作表、字段和样式，复用 `data` / `config`，不另造多种交付格式。

## 表格外观与字段

保留模板原有列顺序和黑白样式，不加彩色标题、条纹表格或状态配色。
单一单位表使用 `单价（元/打）` 或 `单价（元/条）`；混合单位表使用 `单价（元）`，由 `计价单位` 列注明每行按打或条。明细单价单元格只显示数字。
列宽、换行和数字格式可为可读性调整。货号和条码是文本，完整显示，不用科学计数法。
来源路径、版本差异和长篇核对记录放材料索引；表内备注只留必要的业务说明。
保留可用的商品图片；若图片仍在源文件，明确其位置，不伪造已补图。

`data` 需要货号、品名、条形码、单价、装箱数、件数、总数量、总立方、供应商，
最后一行用 `DATA_END`。沿用模板其余字段，增加 `计价单位` 列并填写该商品的实际单位。
`单价` 为 CNY/计价单位，`装箱数` 与 `总数量` 使用同一计价单位；`件数` 为符合标准装箱规格的整件数。
女士内裤保留条，袜子按打；男士内裤等其他品类按已确认的业务口径，不套用女士或袜子的规则。

`config` 保留柜号、计算所需费用与汇率，以及已查到的 ETA，用「参数 / 值 / 说明」简表。
说明只写币种、暂估或汇率日期等必要信息。厂家承担内陆费时直接填 `内陆费 = 0`，
不另加承担方行。ETA 单独一行显示预计到港日期，说明注明查询日期；精简参数时不得删除它。
完整船期节点、来源、处理状态和长篇证据放材料索引。ETA 不代表实际到仓或入库日期。
未知采购价或费用保持空白，不用 0 代替。费用和汇率按[当前成本参数规则](../../container-cost/references/costing.md)准备，包括清关暂估150万、人民币换比索手续费和中行美元报价。整柜明细或货值不完整时，IVA 不显示估算金额；资料完整但运费缺失时，公式须待运费填入后再计算。除工作簿原有 `data`、`config` 外不加 sheet。
箱数、货值和体积可全柜合计，数量按打、条分别合计，不能把不同单位相加。合计放在 `DATA_END` 后；成本程序只读取明细。

## 换算与核对

先确认源表计价单位，用数量单位、装箱规格和金额公式交叉核对，不只相信列标题。
对已确认按双的袜子：单价乘 12，装箱数和总数量除以 12；件数、货值和体积不变。
女士内裤按条销售和入库，保留元/条、条/箱及总条数，不除以或乘以 12。
已按打的行保持原值。其他商品只有已确认目标销售单位为打时才转换；单位不明先列待补。
不能只换单价而留下双数，也不能把已换好的单价再次乘 12。

袜子可复用 `container-cost/src/calculate.ts` 的纯函数 `normalizePricingUnits`，
仅传有确定来源的数值行，输出标记为打；不因此调用 `calculate` 或 `process`。
尚缺价格的行仍换算已确认数量，单价和金额继续留空。

保存前后按源行核对：
- `件数 × 装箱数 + 散件数 = 总数量`，各供应商合计与原件相同；发生转换的行可按转换因子回到源数量，保持原单位的行与源数量相同。
- `单价 × 总数量 = 货值`，单位转换前后逐行和整柜货值不变。
- 原始尾包不作为新的装箱规格。标准整理表按同货号的标准装箱数保留整件，尾包总数量写入末尾 `散件数` 列，和商品计价单位一致；原包装件数及源行留在索引。
- 例如 MF401：4件×80打＋110打尾货，整理为装箱数80、件数4、散件数110、总数量430。散件超过一整箱也不重新凑箱。
- 合并同货号前核对单位、单价及规格一致，总数量、货值和总立方累加；单价不同或规格归属未确定时不能强行合并。只有尾货而没有整件的商品可填件数0，标准装箱规格必须有来源。
- `总立方` 包含原尾包体积，不能用整件数乘标准箱体积代替；运输包装总件数与入库整件数分开核对。
- 未压缩箱体积、实际装柜体积和整柜提单体積分开留证，不能互相冒充或写错产品 boxVolume。

缺条码先只读匹配 K2046 同货号。系统已有无主条码商品保留空白例外，不能取组件条码代替。
原表与系统条码冲突、新货号或混合货号分别记录，不能只靠格式校验就认定可交接。

保存后独立读回字段、单位、行数、数量、货值和公式缓存，并查看工作表排版。
业务上缺什么就标什么；没有事实依据的价格不能因凑齐模板而填入。


## 逐列验收

验证脚本使用模板17列加「计价单位」，有尾货时追加「散件数」；单价标题按本规范改名。
公式必须在 Excel 或可用的表格计算引擎重算并保存；openpyxl 不负责计算，
脚本不会用自行算出的值冒充文件公式缓存。报告记录工作簿 SHA-256，修改后须重跑。

| 列 | 自动检查 | 必须对照的原件事实 |
| --- | --- | --- |
| 货号、条形码、品名、供应商 | 文本、必填；条码校验位 | 原行及 K2046 匹配，主条码、商品和供应商归属 |
| 图片、工艺、备注 | 非空单元格为文本（嵌入图片另看） | 图片是否对应本行，工艺原文、尾包归属及必要说明 |
| 单价、装箱数、件数、总价格、总数量 | 正数、整件数、数量乘积及货值乘积 | 原计价单位、乘除 12、逐行和整柜货值不变 |
| 立方、长、宽、高、总立方 | 正数、厘米尺寸乘积、箱体积乘件数 | 未压缩尺寸与实际分摊体积区别；差异须查证，不机械改数 |
| 计价单位 | 每行必须明确为打或条 | 原表口径已确认且未重复转换 |
| config 参数、值、说明 | 三列、参数唯一、费用/汇率类型、柜号、ETA 日期 | 费用范围和币种、承担方、汇率来源、ETA 查询日期 |

在材料索引按字段组记录原件文件及行号/单元格、比较结果与例外，不能把生成表本身
当作独立来源。自动 PASS 仅表示表内规则通过，不能代替这些来源核对。
导入前逐货号对照 K2046 的库存单位、装箱数及包装层级。PCS、DOZ 等标记结合档案和业务口径核对；包装数量不能单独用来猜单位。发现条/打不一致先修正整理稿，不通过改写商品档案迁就错误换算。
